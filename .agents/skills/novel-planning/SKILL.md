# Novel Planning

라이트노벨/웹소설 프로젝트의 기획 전 과정을 안내하는 절차 가이드다. `story-bible-planner`(Phase 2)와 `season-planner`(Phase 3)가 이 스킬을 참조한다.

---

## Phase 경계 원칙

이 스킬이 다루는 작업을 Phase별로 명확히 구분한다. 경계를 넘지 않는 것이 스토리의 유연성을 보장한다.

| Phase | 담당 에이전트 | 이 스킬에서 허용되는 작업 |
|-------|-------------|------------------------|
| **Phase 2** | `story-bible-planner` | 스토리 바이블 전체 + 시즌 씨앗만. 챕터 플롯 ❌ 시즌 상세 아크 ❌ |
| **Phase 3** | `season-planner` | 시즌 아크 확장. 챕터별 플롯 비트 ❌ 장면 묘사 ❌ |
| **Phase 4** | `chapter-plotter` | 챕터 플롯 설계. 산문 집필 ❌ |

---

## Phase 2 절차: 스토리 바이블 작성

### 단계 1 — 입력 정규화

사용자 입력과 `{slug}/P01_research/01_reference.md`에서 다음을 추출·정리한다.

- 확정된 정보: 장르, 분위기, 주인공 아이디어, 독자 타겟
- 미확정 정보: 구체적 설정이 없으면 `(미확정)` 표시 후 이후 단계에서 설계
- 상충 정보: 입력 간 모순이 있으면 오케스트레이터를 통해 사용자에게 확인 요청
- 참고 작품: 언급된 경우, 어떤 요소를 가져오고 어떤 요소를 피하는지 명시

**진입 조건:** 장르·핵심 아이디어가 없으면 다음 단계로 진행하지 않는다.

---

### 단계 2 — 콘셉트 카드

작품의 핵심을 **한 문장 로그라인**으로 압축한다.

**형식:** `[주인공]은 [목표]를 이루기 위해 [장애물]과 싸우는 이야기다.`

로그라인이 이 형식으로 완성되지 않으면 설정이 아직 정리되지 않은 것이다. 이 단계를 통과해야 단계 3으로 진행한다.

**로그라인 체크리스트:**
- [ ] 주인공이 명확한가?
- [ ] 목표(의식적 욕망)가 한 단어로 표현 가능한가?
- [ ] 장애물이 구체적인가?
- [ ] 한 문장 안에 모두 들어가는가?

---

### 단계 3 — 장르/톤 카드

| 항목 | 내용 |
|------|------|
| 주 장르 | 이세계 판타지 / 현대 로맨스 / SF / 학원물 / 무협 등 |
| 부 장르 | 최대 2개 (예: 먼치킨 성장물 + 하렘) |
| 톤 키워드 | 4개 이하 (예: 경쾌함·긴장감·따뜻함·어두움) |
| 참고 작품 톤 | 가져올 요소 / 피할 요소 |
| 금지 톤 | 이 작품이 의도적으로 피해야 할 분위기 |

### 단계 4 — 주인공 카드

| 항목 | 내용 | Canon |
|------|------|-------|
| 이름 | | locked |
| 나이·성별 | | locked |
| 외형 키워드 | 3~5개 단어 | draft |
| 성격 키워드 | 3~5개. 욕망·결핍과 모순되지 않게 | draft |
| 습관적 동작·버릇 | 2~3개. 생각·거짓말·긴장 시 반복 행동 | draft |
| 감정 반응 패턴 | 분노·불안·기쁨 시 신체 반응 각 1줄 | draft |
| 내면 욕망 | "~를 원한다" — 의식적 목표 | locked |
| 내면 결핍 | "~가 두렵다 / ~가 없다" — 무의식적 약점 | locked |
| 시작 상태 | 1시즌 시작 시점 상황 | draft |
| 핵심 능력/특기 | | locked |
| 말투 특징 | 대사 예시 1~2줄 포함 | draft |
| 성장 방향 | `### sNN 성장 방향` 단위로 시즌마다 append | draft |

**주의:** 욕망과 결핍이 모두 정의되지 않은 주인공 카드는 미완성이다. 둘 사이에 긴장이 없으면 내면 갈등이 없는 캐릭터가 된다.

주인공 카드 끝에는 아래 구조를 만든다. Phase 2에서는 s01 방향만 작성하고, 시즌 종료 상태는 Phase 8.7 롤업이 append한다.

```markdown
## 성장 방향

### s01 성장 방향
{이번 시즌에 내적으로 어떻게 달라져야 하는가}

## 시즌별 상태 변화

<!-- Phase 8.7 롤업이 아래 형식으로 시즌마다 append한다. -->
### sNN 종료 시점 ({CCC}화)
- **시작 대비 변화:** {1~2줄. 변화가 없으면 "의도된 무변화"로 명시}
- **관계 변화:** {주요 관계 이동}
- **획득·상실:** {소지품·지위·능력}
- **다음 시즌 이월:** {미해결 상태, 모르는 사실}
```

### 단계 4.5 — POV Voice Profile

`P02_bible/voice_profile.md`에 작품 고유 화자 규칙을 별도로 작성한다. 주인공 카드의 말투 특징은 대사와 인물 성격 중심이고, voice profile은 본문 내레이션·비유·묘사 문단을 닫는 반응 중심이다.

필수 항목:
- 기본 화자 리듬
- 좋은 패턴
- 문장 리듬
- 묘사 문단 닫는 방식
- 피해야 할 것
- 대표 예문 3개 이상

주인공의 화자 개성이 약한 작품도 빈 파일로 두지 않는다. 최소한 "캐릭터 카드의 말투와 시즌 바이블 톤을 따른다"는 기본 profile을 만든다.

다중 POV 작품은 한 파일 안에 `공통 서술 원칙`을 먼저 두고, 그 아래 `POV별 Voice Profile` 하위 섹션을 만든다. 각 POV마다 본문 내레이션·비유·묘사 문단을 닫는 반응이 어떻게 다른지 구분한다.

---

### 단계 5 — 주요 캐릭터 카드

히로인·라이벌·빌런·조연을 각각 별도 파일로 작성한다. 모든 프로젝트에 반드시 존재할 필요는 없다.

각 파일 최소 항목:
- 이름, 나이, 역할(주인공과의 관계 기준)
- 외형 키워드 3개
- 성격 키워드 3개
- 습관적 동작·버릇 1~2개 (첫 등장과 재등장 식별에 사용)
- 감정 반응 패턴 (주요 감정 1~2개)
- 욕망과 결핍
- 말투 특징 + 대사 예시 1~2줄
- 주인공과의 관계 동학 (긴장·협력·성장 기여 방식)
- 성장 방향. 히로인·라이벌·빌런은 `## 성장 방향` 아래 `### sNN 성장 방향`을 필수로 작성한다. 조연은 선택이지만 시즌 아크에서 역할이 있으면 필수다
- Canon 상태

**경고:** 조연이 주인공을 일방적으로 지지하기만 하면 드라마틱 긴장이 사라진다. 각 주요 캐릭터는 주인공의 결핍을 다른 방식으로 자극해야 한다.

주요 캐릭터 카드도 끝에 아래 구조를 만든다. 기존 시즌 기록은 덮어쓰지 않는다.

```markdown
## 성장 방향

### s01 성장 방향
{이번 시즌에 내적으로 어떻게 달라져야 하는가. 의도된 무변화도 근거와 함께 명시}

## 시즌별 상태 변화

<!-- Phase 8.7 롤업이 아래 형식으로 시즌마다 append한다. -->
### sNN 종료 시점 ({CCC}화)
- **시작 대비 변화:** {1~2줄. 변화가 없으면 "의도된 무변화"로 명시}
- **관계 변화:** {주요 관계 이동}
- **획득·상실:** {소지품·지위·능력}
- **다음 시즌 이월:** {미해결 상태, 모르는 사실}
```

`supporting.md`의 인물 항목이 **12개를 초과하면** 시즌별 파일로 분리한다.

- `supporting.md`를 `supporting_s01.md`, `supporting_s02.md`처럼 나눈다
- 분리 기준은 첫 등장 시즌이며, 이후 시즌에도 등장하는 인물은 첫 등장 시즌 파일에 남긴다
- 분리 시 `characters/README.md`에 `인물 | 첫 등장 시즌 | 카드 파일` 색인을 만들고 갱신한다
- 에이전트는 먼저 `characters/README.md`를 읽어 필요한 카드 파일만 연다

### 단계 6 — 세계관 카드

세 파일로 분리한다.

**`world_rules.md`:** 이 세계가 현실과 다른 핵심 규칙.
각 규칙 항목: `규칙 이름 — 설명 — 왜 이야기에 필요한가`

**`magic_system.md` / `system_rules.md`:** 마법·능력·시스템 규칙. 반드시 포함:
- 능력의 원천과 발현 방식
- **한계와 비용** (이것 없이는 갈등이 사라진다)
- 예외 규칙과 그 조건

**`factions.md`:** 주요 세력 2~5개. 각 세력: 목표·자원·약점·주인공과의 관계.

**`locations.md`:** 주요 무대. 각 장소: 분위기 키워드·이야기적 기능·특이 규칙.

**`P02_bible/glossary.md`:** 작품 전체의 표준 표기를 관리한다. 형식은 `표준 표기 | 금지 표기(변형) | 분류(인명/지명/능력/호칭/아이템) | 첫 등장`이며, Phase 2에서 알려진 고유명사를 모두 등록한다.

---

### 단계 7 — 관계 맵

주요 인물 간 관계를 텍스트 맵으로 정리한다.

형식: `[인물 A] ↔ [인물 B]: 관계 유형 — 표면 관계 / 숨겨진 긴장`

**체크리스트:**
- [ ] 모든 주요 인물 쌍이 포함되어 있는가?
- [ ] "표면 관계"와 "숨겨진 긴장"이 다른가?
- [ ] 시즌이 진행되면서 관계가 변화할 여지가 있는가?

---

### 단계 8 — 핵심 갈등 카드

| 층위 | 정의 형식 | 내용 |
|------|----------|------|
| 외부 갈등 | "주인공이 물리적으로 싸우는 것은?" | |
| 내부 갈등 | "주인공이 내면에서 극복해야 할 것은?" | |
| 대인 갈등 | "어떤 관계가 가장 크게 마찰하는가?" | |
| 사회적 갈등 | "세계관 차원에서 충돌하는 가치는?" | |

4개 층위가 서로 연결되어야 한다. 외부 갈등만 있고 내부 갈등이 없으면 캐릭터가 성장하지 않는다.

---

### 단계 9 — 시즌 씨앗

각 시즌의 핵심 질문을 한 문장씩 정의한다. 이것이 Phase 3에서 확장될 씨앗이다.

**형식:** `시즌 N: "[핵심 질문 한 문장]"`

**Canon 상태 규칙:**
- 시즌 1 씨앗: `[LOCKED]` 또는 `[DRAFT]`
- 시즌 2 이상: `[DRAFT]` 또는 `[CANDIDATE]`

**범위 제한:** 시즌 씨앗에는 핵심 질문만 포함한다. 플롯 비트·챕터 배치·장면 묘사는 이 단계에서 작성하지 않는다.

---

### 단계 10 — Canon 상태 분리

| 상태 | 태그 | 의미 |
|------|------|------|
| **locked** | `[LOCKED]` | 이후 에이전트가 명시적 개정 없이 변경 불가. 변경 시 오케스트레이터에 에스컬레이션 |
| **draft** | `[DRAFT]` | 변경 가능. 변경 시 이유를 `P02_bible/open_questions.md`에 기록 필수 |
| **candidate** | `[CANDIDATE]` | 아이디어 수준. 원고에서 확정 사실로 서술 금지 |

`P02_bible/02_story_bible.md` 상단에 항목별 Canon 상태 요약 표를 작성한다.

## Phase 3 절차: 시즌 구조 확장

### 원칙

- `P02_bible/season_seeds.md`의 시즌 씨앗을 확장해 각 시즌의 아크를 설계한다
- **시즌 1은 완전 상세**, 시즌 2 이후는 방향/씨앗 수준이 기본. 사용자 명시 요청 시 완전 상세 가능
- **챕터별 플롯 비트는 작성하지 않는다** — 그것은 Phase 4다

### 각 시즌 바이블 필수 항목

1. **시즌 제목** — 작업용 제목 (한 단어~짧은 구절)
2. **시즌 역할** — 전체 시리즈에서 이 시즌의 서사적 기능 (한 문장)
3. **시즌 핵심 질문** — 시즌 끝에 독자가 답을 얻는 질문
4. **시작 상태** — 주인공·세계의 시즌 시작 상태
5. **종료 상태** — 피날레 직후 상태 (시작 상태와 비교)
6. **주요 갈등** — 외부·내부·대인·사회 층위별 한 문장
7. **주요 캐릭터 아크** — 주요 인물별 `시작 상태 → 종료 상태 — 변화 원인`
8. **주요 사건** — 반드시 발생해야 하는 사건 목록 (순서 아님, 챕터 배치 ❌)
9. **심을 복선** — 이번 시즌에서 심는 복선 + 예정 회수 시즌
10. **회수할 복선** — 이번 시즌에서 회수하는 복선 + 회수 방식
11. **이월 복선** — 다음 시즌으로 넘기는 복선
12. **챕터 규격** — 목표 자수(기본 4,500~5,500자), 씬 수(2~4개), 대사 비중(30~50%). 사용자 지정이 있으면 그 값을 사용
13. **시즌 피날레** — 핵심 질문에 대한 답 + 독자에게 제공하는 만족 요소
14. **다음 시즌 훅** — 피날레 직후 심는 다음 시즌 씨앗 (한 문장)

### 피날레 설계 원칙

피날레는 두 가지를 동시에 이행해야 한다:
1. **이번 시즌의 핵심 질문에 답한다** — 모호하게 끝내지 않는다
2. **다음 시즌 훅을 심는다** — 단, 이번 시즌의 약속을 먼저 이행한 후

피날레가 다음 시즌 예고편으로만 끝나면 독자는 배신감을 느낀다.

### 복선 흐름 추적

|----------|----------|--------------|---------|
| | | | 미회수 / 회수 완료 / 이월 |

## Phase 8.7 절차: 인물 카드 롤업

시즌 N 종료 후 `story-bible-planner`가 수행한다. 이 절차는 새 설정을 발명하는 단계가 아니라 `character_state_table.md`, `continuity_log.md`, 시즌 원고에 이미 기록된 변화를 캐릭터 SSOT로 수렴시키는 단계다.

1. 오케스트레이터가 `critical_status.md`의 최신성·`open` 0건과 미완료 롤업 저널 부재를 확인한 뒤에만 작업한다
2. `continuity_log.md`의 `### 카드 미등재 인물` 후보 중 고유 이름·대사·2개 챕터 이상 등장 조건을 충족한 인물만 카드로 등재한다
3. 모든 등장 인물 카드의 `## 시즌별 상태 변화`에 `### sNN 종료 시점`을 append한다. 기존 시즌 기록은 수정하거나 덮어쓰지 않는다
4. `P03_planning/03_season_plan.md`에 다음 계획 시즌이 있을 때만 주인공·히로인·라이벌·빌런과 다음 시즌 아크에 참여하는 조연의 `## 성장 방향`에 `### s{N+1} 성장 방향` 초안을 append한다. 마지막 계획 시즌이면 `s{N+1}` 방향을 생성하지 않고 시즌별 상태 변화의 종료 상태를 시리즈 완결 상태로 기록한다
5. `relationships.md`를 종료 상태로 갱신하되 이전 관계의 변화 원인을 시즌 상태 변화 항목에 남긴다
6. `supporting.md`가 12명을 초과하면 첫 등장 시즌 기준 `supporting_sNN.md`로 분리하고 `characters/README.md` 색인을 만든다
7. 결과를 원본 경로에 직접 쓰지 않는다. 신규·갱신·분리할 카드, `characters/README.md`, `relationships.md`를 `P04_continuity/sNN/_archive/.staging/new-active/` 아래에 프로젝트 상대 경로 그대로 작성하고, 신설/교체 대상 목록과 예상 바이트를 `continuity-keeper`에 전달한다
8. 로그와 원고가 충돌하면 임의로 합치지 않고 스테이징을 중단해 G7.7 다이제스트의 보류 항목으로 보고한다

스테이징 결과는 `continuity-keeper`의 원자적 승격과 G7.7 사용자 승인을 거치기 전 다음 시즌의 확정 Canon으로 사용하지 않는다.
